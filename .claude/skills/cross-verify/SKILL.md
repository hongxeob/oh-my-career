# cross-verify

## Overview

`/verify-resume`가 통과시킨 초안을 **문맥을 공유하지 않는 서브 에이전트들**로 다시 검증한다.

verify는 초안을 만든 흐름 안에서 돌기 때문에, 초안이 세운 프레임을 그대로 받아들이는 앵커링이 생긴다.
**실제로 이 방식으로 놓쳐서 제출까지 간 적이 있다.** 검색 응답 개선 수치가 색인 파이프라인 줄에 붙었고,
상품 리스트 조회 수치가 다른 영역의 성과로 나갔다.
**수치 자체는 전부 원본에 있었기 때문에 FAIL이 뜨지 않았다.** 틀린 것은 값이 아니라 **어느 줄에 붙었는가**였다.

이 스킬은 그 축을 따로 검증한다. 각 에이전트는 **초안이 왜 그렇게 썼는지 모르는 상태로** 원본과 대상 문서만 받는다.

## Input

- 팩트 원본: `src/.my/my-resume.md` — 특히 상단 세 블록
  - ⚠️ **수치 귀속표** (수치 ↔ 무엇의 수치인가 ↔ 프로젝트)
  - 🧭 **시스템 경계** (프로젝트별로 어느 시스템에 붙는 수치인가)
  - 🚫 **인용 금지 목록**
- 검증 대상: **verify 리포트가 추천한 버전 1개.** 하이브리드 추천이면 베이스 + 이식 대상까지 최대 2개
  - ⚠️ **와일드카드(`draft-*.md`) 금지.** 예전엔 A/B/C 전부를 대상으로 삼았고, 서브 에이전트 5개가 각각 다시 읽어
    **버려질 초안 2개를 6중으로 검증**했다. 바로 앞 단계가 이미 한 버전을 골라놨는데도 그랬다
  - 인자로 `4_refine/{company}-final.md`를 받았으면 그 파일 하나만
- JD: `src/.my/jd/pending/{company}_jd.md` (또는 `src/.my/jd/applied/`)
- 앞 단계: `outcome/{company}/2_verify/{company}-verify.md`

## Output

- `outcome/{company}/2_verify/{company}-cross-verify.md`

## Process

### Step 1: 원본 상단 세 블록만 읽는다 (전문 금지)

```bash
sed -n '16,81p' src/.my/my-resume.md     # 수치 귀속표(16-48) + 시스템 경계(49-60) + 인용 금지(61-81)
```

**원본 전문을 읽지 않는다.** 45KB 중 이 단계에 필요한 건 5.8KB뿐이고, 경력 본문 28KB를 컨텍스트에 올릴
이유가 없다. 개별 문장의 근거를 확인할 일이 생기면 그때 `grep -n "<수치>" src/.my/my-resume.md`로 그 줄만 본다.

발췌한 블록은 **그대로 둔다.** 요약하지 않는다 — 서브 에이전트에 원문으로 넘긴다.
세 블록 중 하나라도 원본에 없으면 중단하고 사용자에게 알린다(원본에 검증 기준이 없다는 뜻이다).

⚠️ 위 줄 번호는 2026-09 기준이다. `grep -n '수치 귀속표\|시스템 경계\|인용 금지 목록' src/.my/my-resume.md`로
먼저 확인하고, 어긋나 있으면 실제 줄 번호를 쓴다.

### Step 2: 서브 에이전트 5개를 병렬로 띄운다

`Agent` 도구를 **한 메시지에 5개 호출**해 동시에 실행한다. `subagent_type`은 `general-purpose`.

⚠️ **각 프롬프트에 초안의 의도·전략·이전 리뷰 결과를 넣지 않는다.** 앵커링을 없애는 것이 이 단계의 목적이다.
넘기는 것은 ① **그 축에 필요한 블록만** ② 대상 파일 경로 ③ 그 에이전트의 검증 축, 이 셋뿐이다.

**축마다 필요한 재료가 다르다. 전원에게 같은 것을 넘기지 않는다.**

| # | 축 | 찾는 것 | 넘길 재료 |
|---|---|---|---|
| A | **수치 귀속** | 문서의 모든 숫자를 뽑아 귀속표와 1:1 대조. 값이 맞아도 **"무엇의 수치인가"가 다르면 지적** | 귀속표(16-48행)만 |
| B | **시스템 경계** | 각 수치가 붙은 문장이 그 수치의 프로젝트·시스템과 같은지. 다른 시스템 성과로 넘어간 것 지적 | 시스템 경계(49-60행)만 |
| C | **인용 금지** | 🚫 목록 항목이 표현을 바꿔서라도 들어갔는지. 수치 없이 주장만 남은 형태도 포함 | 인용 금지(61-81행)만 |
| D | **원본 미존재** | 문서의 사실 주장 중 원본에서 근거를 못 찾는 것. 원본보다 강해진 표현("전면", "최초", "단독")도 포함 | **원본 파일 경로 + grep 권한** (아래 참조) |
| E | **JD 과장** | JD 요건 대응 문장이 실제 경험보다 넓게 읽히는지. 미경험 영역이 경험처럼 읽히는 자리 | **JD 파일 경로** (원본 블록 불필요) |

⚠️ **D축에 발췌 블록만 주지 않는다.** "원본에 근거가 없다"는 판정은 원본 전체를 볼 수 있어야 내릴 수 있는데,
예전엔 상단 3블록만 주고 그 판정을 시켰다. 그 결과 **원본 본문에 멀쩡히 있는 항목을 "근거 없음"으로 잘못 지적**했다
(이전 직장 기술 스택의 한 항목이 원본 본문에 멀쩡히 있었는데 발췌에는 없었다). D에게는 원본 **경로**를 주고
`grep -n "<주장>" src/.my/my-resume.md`로 직접 찾게 한다. 못 찾은 것만 ❌로 올리게 하고,
**"❌를 올리기 전에 표기를 바꿔 최소 2번 더 grep했는지"**를 프롬프트에 명시한다.

각 에이전트에게 이 출력 형식을 강제한다:

```
| 위치(파일:줄) | 문서 표현 | 원본 근거 | 판정 | 고친 문장 |
```

판정은 `❌ 오귀속` / `❌ 근거없음` / `⚠️ 과장` / `✅ 일치` 넷 중 하나. **"고친 문장" 열을 비워두지 못하게 한다.**

### Step 3: 결과 병합

- 같은 문장을 여러 에이전트가 지적하면 한 줄로 합치고, 지적한 축을 모두 표기한다(중복 지적 = 신호가 강한 것)
- 에이전트끼리 판정이 엇갈리면 **원본을 직접 다시 읽어 오케스트레이터가 판정**한다. 다수결로 정하지 않는다
- 서브 에이전트 보고를 그대로 믿지 않는다 — ❌ 판정은 전부 원본에서 한 번 더 확인한다

### Step 4: 게이트 판정

```
❌ 오귀속 1건 이상   → BLOCK. 고치기 전에는 /review-resume로 넘어가지 않는다
❌ 근거없음 1건 이상  → BLOCK
⚠️ 과장만 있음       → PASS (조건부). 수정 권고를 남기고 진행
전부 ✅              → PASS
```

### Step 5: 저장

`outcome/{company}/2_verify/{company}-cross-verify.md`:

```markdown
# {company} 교차검증 (독립 서브 에이전트)
생성일: {date}
검증 대상: {대상 파일}
게이트: PASS / BLOCK

## 1. 게이트 판정
{BLOCK이면 사유를 먼저}

## 2. 지적 목록 (심각도순)
| 위치 | 문서 표현 | 원본 근거 | 판정 | 지적한 축 | 고친 문장 |

## 3. 축별 요약
| 축 | 검사 건수 | ❌ | ⚠️ | ✅ |

## 4. verify 리포트가 놓친 것
{2_verify가 ✅로 통과시켰는데 여기서 ❌가 난 항목 — 없으면 "없음"}
```

## Critical Rules

- **수치가 원본에 있다는 것만으로 통과시키지 않는다** — 붙은 자리가 맞아야 통과다. 이 스킬의 존재 이유다
- **서브 에이전트에 초안의 전략·의도·이전 리뷰를 넘기지 않는다** — 문맥을 주면 이 단계는 verify의 복사본이 된다
- **고칠 문장을 만들되 파일을 직접 고치지 않는다** — 수정은 `/refine-resume`가 한다
- 원본에 없으면 만들지 않는다. "커버레터로 보완" 같은 정직한 대안을 쓴다

## Next Step

```
✅ 교차검증 완료 → outcome/{company}/2_verify/{company}-cross-verify.md

PASS  → ▶ **이어서 /review-resume 를 바로 실행한다.**

BLOCK → 🛑 **여기서 멈춘다.** 지적 목록을 사용자에게 보고하고 답을 기다린다.
        오귀속은 제출 사고로 직결되므로 자동으로 고치고 넘어가지 않는다.
        사용자가 진행을 지시하면 /refine-resume 로 반영한 뒤 /cross-verify 재실행.

이 리포트가 없거나 BLOCK이면 /review-resume 가 시작 자체를 거부한다 (건너뛰기 방지).
```

**재실행은 변경분 우선으로 좁힌다.** 첫 바퀴는 전 문서 5축 풀스캔이지만, 두 번째 바퀴는 5축을 유지하되
**고친 문장과 그 문장이 속한 섹션**으로 범위를 좁힌다. Step 2가 "고친 문장" 열을 강제하므로 무엇이 바뀌었는지
이미 알고 있다. 단 **섹션을 통째로 지운 수정은 예외** — 다른 곳의 근거가 함께 사라지므로 풀스캔한다
(2026-09: 개인 프로젝트를 빼면서 `Caffeine`의 유일한 근거가 죽었는데 기술 스택 표에는 남아 있었다).

> **이어달리기 규칙** — 파이프라인은 사용자가 매 단계 커맨드를 치지 않아도 이어진다.
> 멈추는 곳은 셋뿐이다: ① `/evaluate-jd` 등급 판정 ② `/cross-verify` BLOCK ③ `/final-check` '낮음'.
> 그 외에는 **묻지 말고 다음 스킬을 바로 실행한다.** 중간에 사용자가 끼어들면 그 지시가 우선한다.
