# interview-debrief

## Overview

지나간 면접의 녹취를 받아 **그 자리에 배석했던 시니어 면접관**의 시선으로 복기한다.
목표는 위로가 아니라 **다음 면접의 합격률**이다.

이 스킬의 복리는 **회차 누적**에서 나온다. 단발 리포트는 절반의 가치다 — 반복되는 실수를 추적하는 게 본체다.

## Input

- **녹취 텍스트** (필수) — 사용자가 붙여넣거나 파일 경로 제공
- `src/my-resume.md` — 팩트 대조 기준 (**필수로 읽는다**)
- `src/applied/{company}_jd.md` 또는 `src/pending/{company}_jd.md` — 평가 축 가중치
- `outcome/interview/debrief-index.md` — 이전 회차 누적 (있으면 반드시 읽는다)

## Output — 파일 3개

```
outcome/{company}/interview/{company}-debrief-{N}차.md   # 리포트 본체
outcome/{company}/interview/raw/{company}-{N}차-녹취.md   # 원본 녹취 보존
outcome/interview/debrief-index.md                        # 회차 누적 (전 회사 공통, 갱신)
outcome/interview/question-bank.md                        # 실제 받은 질문 은행 (전 회사 공통, append)
```

`{N}차`는 그 회사의 면접 차수. 모의면접이면 `{company}-debrief-모의{N}차.md`.
`src/`·`outcome/` 전체가 gitignore 처리돼 있어 녹취를 그대로 보존해도 외부 노출되지 않는다.

## Process

### Step 0. 입력 확보

- **오디오만 있으면**: 텍스트 변환이 먼저라고 알린다. 클로바노트·다글로·MacWhisper·Whisper. **화자 분리되면 훨씬 정확**하다고 덧붙인다.
- **녹취록**: 바로 진행. 화자 분리가 없으면 문맥으로 추정하고 **추정 구간을 리포트에 표시**한다.
  - 판별 휴리스틱: 질문 어미(`~신가요`, `~죠?`, `말씀해 주세요`)·짧은 발화 = 면접관 / 긴 설명·`~했습니다` = 본인
- **기억 기반 복기 메모**: 진행하되 서두에 **"기억 기반이라 실제 발화보다 정돈돼 보인다. 실제 답변은 더 어수선했을 가능성이 높다"**를 명시한다.

아래 4개는 대화에 이미 있으면 다시 묻지 않는다: 회사·직군·레벨 / 면접 단계 / 면접관 구성·소요 시간 / 특히 신경 쓰이는 지점.

### Step 1. 녹취 정리

STT는 기술 용어를 뭉갠다. 조용히 보정한다 — 카프카→Kafka, 오픈서치→OpenSearch, 색인/인덱싱, 샤드, 역색인, 커넥션 풀, 격리 수준, 부스트 모드→`boost_mode`.
보정이 애매하면 **`[불명확]`으로 남기고 무리해서 해석하지 않는다.**

Q&A 블록으로 분해하고 각각에 메타데이터를 붙인다:

- **유형**: `CS기초` `언어·프레임워크` `데이터베이스` `검색·색인` `인프라·네트워크` `시스템설계` `경험·프로젝트` `트러블슈팅` `컬처핏` `역질문`
- **꼬리질문 깊이** (몇 단으로 파고들었나)
- **면접관 반응**: 넘어감 / 되물음 / 정정함 / 화제 전환 / "좀 더" 요청

⭐ **꼬리질문 깊이가 가장 강한 신호다.** 3단 이상이면 관심이 있었거나 확신이 없었다는 뜻이고, 한 번에 넘어갔으면 충분했거나 이미 포기한 것이다. 어느 쪽인지는 어투와 이후 흐름으로 판단한다.

### Step 2. 기술 평가

**사실 정확성** — 답변에 들어간 기술적 주장을 하나씩 검증한다. **틀린 내용은 반드시 잡는다. 이 스킬의 가장 큰 가치가 여기다.** 자신 있게 말한 내용일수록 더 꼼꼼히 본다.
- 명백한 오류 / 절반만 맞는 설명(어느 조건에서 참·거짓인지) / 용어 오용
- 확신이 안 서면 **"직접 확인해보라"고 솔직히 쓴다. 틀린 피드백은 없는 피드백보다 나쁘다.**

**깊이** — 주니어와 시니어를 가르는 건 지식량이 아니라 **"왜"에 답할 수 있는지**다.
- L1 용어를 안다 / L2 동작을 안다 / L3 왜 그렇게 설계됐는지 안다 / L4 트레이드오프를 걸고 선택한다 / L5 자기 수치와 실패 사례로 뒷받침한다
- 미들 이상 지원이면 **L3가 기본선**, 핵심 질문에서 **L4가 안 나왔으면 개선점**이다.

**경험 서술 밀도** — 구체적 수치(before/after) / 팀이 한 것과 내가 한 것의 구분 / 검토했다 탈락한 대안 / 실패하거나 되돌린 경험. 없으면 **어느 질문에서 넣었어야 했는지 지목**한다.

### Step 3. 🔴 이력서 대조 (프로젝트 고유 — 건너뛰지 말 것)

`src/my-resume.md`를 읽고 녹취와 대조한다.

| 검사 | 판정 |
|---|---|
| 말한 **수치**가 원본에 있는가 | 있음 / **원본에 없음** / **다른 구좌의 수치를 끌어다 씀** |
| 말한 **경험**이 원본에 근거가 있는가 | 있음 / **과장** / **없는 경험** |
| 원본 상단 **수치 귀속표**와 어긋나는가 | (예: 검색 응답 수치를 색인 성능으로 말함) |

🔴 **원본에 없는 걸 말했으면 최우선 지적이다.** 다음 면접에서 같은 말을 하면 레퍼런스 체크나 2차에서 무너진다.

### Step 4. 소프트스킬 평가

기술만큼 자주 떨어지는 이유가 여기다.

- **두괄식** — 결론부터 말했나, 서론이 길어 끊겼나
- **답변 길이** — 30초 미만(부실) / 2분 초과(초점 흐림) 구간 지목
- **모를 때** — 인정하고 접근법을 말했나 / 얼버무렸나 / **모르면서 아는 척했나(가장 위험, 실제 발화로 지목)**
- **질문 의도** — 물은 것과 다른 답을 한 구간
- **되묻기** — 모호한 설계 문제에서 요구사항을 확인했나
- ⭐ **면접관에게 답을 되물었나** — "어떻게 하면 좋을까요?" 류. **판단을 보여주고 멈춰야 할 자리다**
- **말버릇** — 필러(`어…`, `약간`, `~같아요`), 어미 흐림, 자기 축소(`제가 잘은 모르지만`). **빈도를 센다** — "필러가 많았다"보다 "'약간' 30분에 20회"가 고치기 쉽다
- **방어성** — 지적받고 변명했나, 인정하고 대안을 냈나
- **일관성** — 앞뒤 답변 충돌 지점 (면접관이 반드시 잡는다)
- ⭐ **회복력** — **무너진 답변 직후 3분**이 어땠는지. 면접은 그 구간에서 갈린다

### Step 5. 면접관 힌트 채굴 (놓치면 손해)

면접관은 자주 답을 흘린다 — *"기술적으로 흔히 쓰는 방식을 하나 말씀드리면…"*, *"저희는 보통 ~하는데요"*.

- 그 발화를 **전부 뽑아낸다.** 그 팀의 실제 스택·기대 답안·현재 겪는 문제가 거기 있다
- 질문 구성 자체도 역추론 재료다 (무엇을 반복해 물었나 = 지금 아픈 곳)

### Step 6. 리포트 작성

```markdown
# [회사] [직군] [N]차 기술면접 복기 — [날짜]

> 입력: [녹취 / 화자 분리 여부 / 기억 기반 여부]

## 한 줄 총평
[면접관이었다면 받았을 인상 2-3문장. 미화하지 않는다.]

## 통과 예측
**통과 / 보류 / 탈락** — 근거 3줄. 확률로 말할 수 있으면 대략치도.

## 점수판
| 항목 | 점수 | 근거 |
|---|---|---|
| 기술 정확성 | ?/5 | |
| 기술 깊이 | ?/5 | |
| 경험 구체성 | ?/5 | |
| 구조적 전달력 | ?/5 | |
| 커뮤니케이션·태도 | ?/5 | |
| 직무 적합성 어필 | ?/5 | |
*[레벨] 기준. 3점 = 그 레벨 평균 합격선. JD가 있으면 JD 필수 항목에 가중치.*

## 🔴 사실 오류 / 이력서 불일치
[Step 2·3 결과. 없으면 "없음"이라고 명시]

## 질문별 분석

- **잘한 점**:
- **문제**:
- **면접관은 이렇게 봤을 것**: (추측)

[핵심 5-8개. 사소한 건 묶는다]

## 답 못한 / 약했던 질문 (그대로 공부 목록이 된다)
| 질문 | 왜 막혔나 | 다음까지 준비할 것 |
|---|---|---|

## 면접관이 흘린 정보
[Step 5 결과 — 그 팀의 스택·기대 답안·현재 문제]

## 잘한 점 (유지할 것)
## 아쉬운 점 (반복하면 계속 떨어진다)

[합·불을 가른 1-3개 지점과 이유]

## 액션 아이템
| 우선 | 할 일 | 왜 | 기한 |
|---|---|---|---|
[5-7개. "CS 공부하기"는 액션이 아니다. "격리 수준별 이상 현상 4가지를 30초 설명으로 정리" 수준]

## 다음 면접 30분 전 체크리스트

```

### Step 7. 🔴 누적 갱신 (건너뛰지 말 것 — 이게 본체다)

**`outcome/interview/debrief-index.md`** 갱신:

```markdown
# 면접 복기 인덱스

| 회차 | 회사 | 단계 | 날짜 | 결과 | 총평 | 리포트 |
|---|---|---|---|---|---|---|

## 🔴 반복 지적 (2회 이상 = 최우선)
| 지적 | 발생 회차 | 횟수 | 상태 |
|---|---|---|---|

## 회차별 점수 추이
| 항목 | 1차 | 2차 | 3차 |
```

- **2회 이상 반복된 지적은 자동으로 최우선 액션 아이템으로 승격**한다. 리포트 본문에도 `🔁 N회째` 태그를 붙인다
- 점수 추이가 **떨어진 항목이 있으면 반드시 지목**한다

**`outcome/interview/question-bank.md`**에 이번에 받은 질문을 append (질문 / 회사 / 유형 / 내 대응 / 준비 상태). 회사가 달라도 질문은 반복된다.

## Critical Rules

- **아부 금지.** "전반적으로 훌륭했습니다"로 시작하면 그 뒤를 아무도 안 읽는다
- **모든 지적에 실제 발화 인용을 붙인다.** 근거 없는 총평은 쓰지 않는다
- **추측과 사실을 구분한다.** 면접관 속마음은 추측, 답변이 틀렸다는 건 사실. 추측은 추측이라고 쓴다
- **사람이 아니라 답변을 평가한다.** "준비가 부족한 사람"이 아니라 "이 답변은 준비가 부족했다"
- **잘한 점도 정확하게.** 없는 걸 만들지 않고 있는 걸 빠뜨리지도 않는다 — 유지할 행동을 모르면 다음에 그것까지 잃는다
- **위축돼 있으면 지적의 양이 아니라 우선순위를 좁힌다.** 20개를 다 못 고친다. 상위 3개를 명확히
- **결과가 나쁠 것 같으면 그렇게 쓴다.** 목적은 시간 낭비 방지다

## Next Step

리포트 후 상황에 맞는 것 **1-2개만** 제안한다. 전부 나열하지 않는다.

- **모범답안 스크립트** — 취약 질문에 대해 **본인 이력으로 만든** 60초 답변. 남의 모범답안은 실제 면접에서 안 나온다
- **꼬리질문 트리** — 이번 질문에서 한 단계씩 더 들어갈 10개
- **모의면접** — 약점 영역 집중. `모의면접-프롬프트.md`의 「이미 답한 주제」 칸에 이번 주제를 넣어 각도를 틀게 한다
- **회사 시그널 분석** — 질문 구성으로 역추론한 팀의 관심사
- **역질문 설계** — 평가에 플러스가 되는 질문
