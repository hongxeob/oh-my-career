# evaluate-jd

## Overview

JD와 원본 이력서를 비교 분석해 **지원 적합도를 A-F 등급으로 평가**한다.
지원 전에 "이 공고가 나에게 맞는가"를 객관적으로 판단하기 위한 사전 필터 단계.

## Input

> 경로 이름(`{RESUME}`, `{JD}`)의 정의는 **CLAUDE.md 「경로 해석」** 한 곳에 있다. 파일을 못 찾으면 스킬을 고치지 말고 그 표를 고친다.

- 원본 이력서: `{RESUME}` (= `src/.my/my-resume.md`)
- JD: `{JD}` (= `src/.my/jd/pending/{company}_jd.md`) (진행 중인 회사면 `src/.my/jd/applied/`에 있을 수도 있음)

## Output

- `outcome/{company}/0_evaluate/{company}-evaluate.md`

## Process

### Step 1: JD 핵심 요건 추출

JD를 읽고 다음을 표로 정리:

| 구분 | 내용 |
|------|------|
| 포지션 | 직함 및 팀 |
| 핵심 업무 | 실제로 하는 일 3-5가지 |
| 필수 역량 | MUST-HAVE 기술/경험 |
| 우대 역량 | NICE-TO-HAVE 기술/경험 |
| 기술 스택 | 명시된 기술 |
| 조직 문화 | 팀 규모, 문화, 일하는 방식 |

### Step 2: 10차원 적합도 스코어링

원본 이력서와 JD를 대조해 각 차원별 1-5점 평가:

| 차원 | 가중치 | 설명 |
|------|--------|------|
| 기술 스택 일치 | 15% | JD 명시 기술 vs 내 기술 |
| 핵심 업무 경험 | 20% | JD 핵심 업무를 해본 적 있는가 |
| 도메인 적합성 | 10% | 산업/도메인 경험 일치 |
| 성장 방향 일치 | 10% | 내 커리어 방향과 맞는가 |
| 시니어리티 매칭 | 10% | 연차/레벨 적합도 |
| 임팩트 어필 가능성 | 10% | 내 성과가 이 JD에서 돋보이는가 |
| 우대 역량 커버 | 10% | NICE-TO-HAVE 중 충족 비율 |
| 차별화 포인트 | 5% | 다른 지원자 대비 특별한 강점 |
| 갭 리스크 | 5% | 치명적 부족 역량 존재 여부 (역산) |
| 문화 적합성 | 5% | 일하는 방식·조직 문화 매칭 |

### Step 3: 종합 등급 산출

가중 평균으로 총점 계산 후 등급 부여:

| 등급 | 점수 | 판정 |
|------|------|------|
| **A** | 4.5-5.0 | 강력 추천 — 거의 완벽한 매칭 |
| **B** | 3.5-4.4 | 추천 — 강점이 갭을 충분히 커버 |
| **C** | 2.5-3.4 | 검토 필요 — 매칭되지만 갭 존재 |
| **D** | 1.5-2.4 | 비추천 — 갭이 강점보다 큼 |
| **F** | 1.0-1.4 | 부적합 — 방향 자체가 다름 |

### Step 4: 상세 리포트 작성

아래 구조로 리포트 생성:

```markdown
# {company} JD 적합도 평가

## 총평
- **등급**: {A-F}
- **총점**: {X.X}/5.0
- **한줄 판정**: {한 문장 요약}

## 스코어카드

| 차원 | 점수 | 근거 |
|------|------|------|
| ... | .../5 | 구체적 근거 1-2문장 |

## 강점 매칭 (이 JD에서 돋보이는 내 경험)
- {이력서의 구체적 성과} → {JD 요건과의 연결}

## 갭 분석 (부족한 부분)
- {부족 역량} → {심각도: 치명적/보완가능/무시가능} → {대응 전략}

## 이력서 커스터마이징 가이드
- 이 JD에 지원 시 강조해야 할 포인트
- 빼거나 축소해도 되는 포인트
- Summary 방향 제안

## 예상 면접 질문 (Top 5)
1. {JD 기반 예상 질문} → {답변에 활용할 이력서 경험}
```

### Step 5: 저장

```
outcome/{company}/0_evaluate/{company}-evaluate.md
```

## Critical Rules

- **이력서에 없는 경험을 강점으로 카운트하지 않는다** — 팩트 기준 엄수
- **감정적 판단 배제** — "좋은 회사니까 지원하자"가 아닌 객관적 매칭
- **갭은 솔직하게** — D/F 등급이어도 정직하게 판정. 시간 낭비를 방지하는 게 목적
- **커스터마이징 가이드는 구체적으로** — "강조하세요" 수준이 아닌 "이 불릿을 상단에, 이 표현을 이렇게" 수준

## Next Step

```
✅ JD 평가 완료 → outcome/{company}/0_evaluate/{company}-evaluate.md

🛑 **여기서 멈춘다. 자동으로 다음 단계를 실행하지 않는다.**
   지원할지 말지는 사용자가 정한다. 등급과 갭 분석을 보고하고 답을 기다린다.

등급 B 이상 → 사용자가 진행을 원하면 /draft-resume
등급 C 이하 → 갭 분석을 근거로 지원 비추천 의견을 함께 낸다
```

> **이어달리기 규칙** — 파이프라인은 사용자가 매 단계 커맨드를 치지 않아도 이어진다.
> 멈추는 곳은 셋뿐이다: ① `/evaluate-jd` 등급 판정 ② `/cross-verify` BLOCK ③ `/final-check` '낮음'.
> 그 외에는 **묻지 말고 다음 스킬을 바로 실행한다.** 중간에 사용자가 끼어들면 그 지시가 우선한다.
